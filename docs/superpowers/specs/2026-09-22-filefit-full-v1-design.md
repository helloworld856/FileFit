# FileFit 完整首版：功能与开源迁移方案

2026-09-22。本方案取代此前的精简设计。用户已确认产品方向，并要求首版功能完整、优先复用开源能力。本文为扩展设计，尚未实施或验证运行效果。

## 推荐路线

选择性迁移 BentoPDF 的 PDF 模块，接入成熟图片处理库，独立构建“输入上传要求 → 自动处理 → 实际校验 → 下载”流程。按 AGPL-3.0 开源路线规划，保留上游来源及版权。

其他方案：整仓派生 BentoPDF 能更快得到现成工具页面，但会继承大量无关功能和耦合；前端加 Stirling-PDF 后端能力广，但引入上传和运维成本，且须逐目录核对许可证。推荐模块迁移以兼顾完整能力和产品定位。

浏览器本地处理，静态部署，Worker 执行重任务。引擎、字体及语言模型同源分发、按需加载；PWA 缓存已下载能力。首次使用需要联网，不能宣传成首次打开即可完全离线。

## 关键产品规则

- 内置“图片 200 KB”“PDF 5 MB”等通用示例，不冒充某考试或机构的官方规定。
- KB/MB 按十进制，KiB/MiB 按二进制，界面明确单位。
- 原文件保持不变；已达标文件默认原样输出，除非用户另选转换或去元数据。
- 不擅自降低指定像素尺寸、删除 PDF 页面或突破质量下限。无法同时满足条件时说明原因。
- 规则变化后旧结果标为待重新验证；只有实际输出通过全部规则才能显示达标。
- 动画不静默取首帧。PNG 的 Canvas quality 参数不能被当作有效压缩策略。
- DPI 必须读回验证，不能仅按像素换算就声称 DPI 达标。
- PDF 默认尽可能保留文字、矢量和链接，但不保证所有特殊表单和签名无损。修改签名文件前明确影响。
- 图片化 PDF 必须主动选择，解释文字、链接、表单等损失；保留文字模式不能静默降级到图片化。
- 页数超过要求时让用户明确选页，不能自动丢页。
- OCR 结果可能有误，需预览；密码只在当前任务内存保留。
- ZIP 默认只含达标结果；未达标文件单独下载并标注。
- 设置和预设可保存，文件和密码默认不持久化；刷新后说明需要重新添加文件。

## 开源候选与核实结果

### BentoPDF

源：https://github.com/alam00000/bentopdf

package.json 标记 AGPL-3.0-only，采用 Vite/TypeScript。仓库功能涵盖 PDF 页面操作、转换、OCR 和压缩。拟选择性迁移适配层和处理逻辑，不假设整个页面可直接嵌入新 UI。

已读取源码：

- https://github.com/alam00000/bentopdf/blob/main/src/js/utils/compress.ts
- https://github.com/alam00000/bentopdf/blob/main/src/js/logic/compress-pdf-page.ts
- https://github.com/alam00000/bentopdf/blob/main/src/js/utils/pymupdf-loader.ts

压缩有两条路径：Condense 调用 PyMuPDF 压缩接口，配置图片重编码、DPI 和字体子集；Photon 将页面栅格化成 JPEG 后重新生成 PDF。现有档位不等于目标字节数求解，需增加自动参数搜索、质量约束和独立校验。

页面逻辑依赖 DOM、全局 state、loader 和密码提示，迁移需要拆分适配，不能仅复制一个文件即算完成。GitHub 目录还确认存在 OCR 工具、HOCR 转换及工作流节点，具体集成待验证。

## 技术结构

规则与预检、任务队列、图片引擎、PDF 引擎、OCR、导出、UI 分离。引擎统一返回文件、警告、能力及进度。UI 面向普通用户，不暴露不必要的技术术语。

压缩保留候选结果，按实际体积选取满足质量约束的输出，不假设压缩参数与结果大小严格单调。不能达标时返回最合适的候选及原因。

初始保护限制：单文件 100 MB、单图 4000 万像素、PDF 200 页、批次 50 文件、OCR 30 页。它们是待压力测试的设计值，不是已验证性能承诺；移动端可能需要降低。及时释放对象 URL、Canvas 和引擎内存，取消任务须真正中断计算。

暂不包含音视频、AI 换背景和 Office 双向高保真转换。遇到 Office 文件明确解释支持范围，不放置无法工作的转换入口。

## 实施与验收

1. 固定上游版本及许可，先跑通 PDF 保留文字压缩和预览，验证 WASM 可同源部署。
2. 实现图片多格式引擎、要求求解和独立校验。
3. 集成 PDF 页面、转换、OCR、密码等功能。
4. 完成批量、预设、报告、国际化、PWA 和部署。
5. 用真实文件验证、完善测试与 GitHub 发布资料。

验收包括：透明/EXIF 图片、异常扩展名、极小体积、固定尺寸冲突、HEIC/AVIF 兼容失败；PDF 文本/链接、页面尺寸、混合方向、加密、损坏、OCR 对齐；队列取消、失败隔离、同名文件、规则变化、ZIP 内容一致性。

保留内容 PDF 输出重新打开，并验证页数、文字提取及样本文档链接，比较渲染外观。网络检查确认文件不上传；首次依赖下载和离线可用范围清楚显示。

交付源代码、自动化测试、实际浏览器验收记录、中英文 README、示例、静态/Docker 部署、开源声明及 CI。未验证的平台与格式如实列明。
