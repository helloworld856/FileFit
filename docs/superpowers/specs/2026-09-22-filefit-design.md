# 文件达标助手 FileFit：首版设计

> 已由 `2026-09-22-filefit-full-v1-design.md` 替代。以下保留为早期方案，不再作为实施范围。

## 目标

帮助普通用户把图片和 PDF 处理到上传要求以内。核心流程：添加文件 → 填写要求 → 处理与预览 → 检查结果 → 下载。

## 方案选择

- 推荐：浏览器本地处理的响应式网页。无需账号，文件不上传服务器，方便试用和开源部署。
- 桌面版：更适合大量或超大文件，但有安装、签名和跨平台维护成本，后续考虑。
- 服务端处理：能使用更完整的 PDF 工具，但有上传隐私、计算成本和服务运维负担，首版不采用。

## 首版范围

### 图片

- 支持 JPEG、PNG、WebP 输入，以及这些格式的输出；不接受动画图片和 HEIC，明确提示支持范围。
- 用户设置最大文件体积，可选输出格式和像素尺寸。
- 尺寸模式包括保持比例限制边长，以及指定宽高后选择裁剪或留白；不默认拉伸。
- JPEG/WebP 使用迭代质量搜索；用户允许自动缩小尺寸时才降低像素尺寸。
- PNG 不宣称可通过质量参数有损压缩；固定尺寸下无法达到体积要求时如实报告。
- 透明图片转 JPEG 时使用可预览的白底。
- 提供批量队列，每项独立显示进度、错误与处理结果；支持逐个下载和打包下载。

### PDF

- 支持普通未加密 PDF，设置目标大小并检查页数和输入大小。
- 明确提供“转为图片型 PDF 后压缩”模式，开始前说明文字将不能直接选中，链接、表单和签名等不保留。
- 使用页面渲染和图像压缩生成新 PDF，逐步调整渲染分辨率与图像质量，实际检查输出字节数。
- 不暗示具备无损通用 PDF 压缩能力；加密、损坏和超出处理上限的文件显示明确错误。
- 不删除页面来满足大小；结果不能达标时提供原因及调整建议。
- PDF 和图片的规则分别设置，不把像素尺寸规则误用到 PDF。

## 交互与视觉

- 中文优先，简洁明亮，突出“文件要求”和“是否达标”，兼容手机与电脑。
- 主页面包含文件区、要求区和结果列表；空状态提供一份可试用示例。
- 图片提供处理前后预览；PDF 提供页面预览、总页数和处理模式说明。
- 结果同时展示原始/输出大小、格式、图片尺寸和逐项验收状态。
- 使用 KB/MB 时明确采用十进制：1 KB = 1000 字节、1 MB = 1000000 字节。
- 原始文件保持不变；未达标结果单独标注，不能混入“一键下载达标文件”。

## 技术结构

- TypeScript、React、Vite，静态部署。
- 图片处理使用浏览器解码及 Canvas；PDF 使用 PDF.js 渲染和 pdf-lib 生成；ZIP 下载使用轻量压缩库。
- 文件解析、规则校验、图片处理、PDF 处理、队列和界面独立成模块。
- 本地打包依赖与字体，不通过第三方服务上传文件；处理任务允许取消。
- 首版串行执行大文件任务，释放 Canvas、对象 URL 和 PDF 资源，避免批量导致内存无限增长。
- 初始输入上限：单文件 30 MB、图片 2500 万像素、PDF 30 页、批次 20 个文件；超出时解释限制。
- 实际设备测试如发现内存不足，降低限制并同步文档，不静默丢页或降低用户指定尺寸。

## 验证标准

- 每项“达标”必须以生成文件的实际字节数、可解码格式和实际尺寸为依据。
- 覆盖透明图片、手机照片方向、极小目标体积、错误扩展名、损坏文件、处理取消和重复添加。
- 固定尺寸和体积要求无法同时满足时，报告未达标，不擅自改规则。
- PDF 输出可重新打开、页数完整；含文本的 PDF 转换后明确显示图片型 PDF 提示。
- 核心规则及压缩边界有自动化测试；实际浏览器验证上传、预览、下载和移动端布局。
- 通过类型检查、生产构建和有意义的处理测试。
